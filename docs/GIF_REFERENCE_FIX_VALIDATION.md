# 参考图 GIF 偶发失败：真实调用与修复记录

日期：2026-11-06。修复版本：0.3.3。

## 已复现的原因

使用仓库中的 `可可子1.jpg`，通过生产代码的参考图映射及
`OpenAICompatibleImageClient.edit()` 提交「可可子吃巧克力」。
请求明确指定 `gpt-image-2.6`、`output_format=gif`、512×512、low、16 帧、40ms。

UUAPI 返回 HTTP 200 和完整的 **2048×2048、16 帧 GIF**（13,015,966 字节）。
累计像素数为 **67,108,864**，超过旧实现对原始文件统一施加的 40,000,000 上限，
因此本地把有效动图判为失败。这次复现的原因不是 HTTP 超时、缺少参考图或模型不支持 GIF。

## 修复行为

- 源文件先检查格式、帧数及解码预算；允许单帧不超过 16,777,216 像素、累计不超过
  134,217,728 像素的超尺寸 GIF 进入逐帧处理。
- 在后台线程逐帧读取完整画面，等比缩小到请求尺寸以内；只保留缩小后的帧，
  不同时持有所有源分辨率帧。透明背景、帧时序与循环次数保留。
- 最终 GIF 仍经过原有 40,000,000 总像素校验；格式错误、单帧、损坏文件及超出源预算的文件仍拒绝。
- 不放大较小文件，不把静态图伪装成动画，不重新调用收费接口。
- 图片发送、永久图库、历史命令和管理预览使用处理后的完整 GIF，不额外归档源尺寸副本。

# AstrBot GPT Image 2 安全生图

这是一个让 AstrBot 的聊天 LLM 直接调用生图能力的插件。图片通过 [UUAPI](https://uuapi.cc/docs) 的 OpenAI-compatible Images API 生成，默认模型为 `gpt-image-2`。

插件的目标不是“收到提示词就无条件出图”，而是把生图做成一条有边界、可控成本的链路：

1. LLM 仅在用户明确要求生图时调用 `generate_image` 工具。
2. 插件先执行本地硬规则，再使用独立 LLM 审核提示词；审核异常默认拒绝。
3. 用户调用频率、用户成功生图数、群成功生图数和并发任务分别限流。
4. 每个任务在入队前冻结发起人、会话路由、提示词、人物参数和引用图片，避免群聊连续调用串图。
5. 提示词命中已配置人物名或别名时，自动携带管理员保存的参考图。
6. 最后仍使用 GPT Image 服务自身的默认上游审核。

## 环境要求

- AstrBot `>= 4.13.0`。人物清单使用 `template_list`，图片上传使用插件配置的 `file` 类型。
- Python 3.10+。
- 一个可调用 `gpt-image-2` 的生图 Key，以及一个可调用聊天模型的独立审核 Key。
- 当前 AstrBot 聊天模型应支持 Function Calling。

## 安装

将本仓库放入 AstrBot 的 `data/plugins/astrbot_plugin_img_gener`，或者在 AstrBot WebUI 的插件页通过仓库 URL/压缩包安装。插件管理器会读取 `requirements.txt` 安装 `httpx`。

## 内置生图管理页（v0.2.0）

重载插件后，在 **AstrBot WebUI → 插件 → GPT Image 2 安全生图 → 可视化视图 → 生图管理** 打开。需要支持插件页面、Bridge 及 `astrbot.api.web` 的新版 AstrBot 和配套 WebUI；仅满足基础聊天功能的 `>= 4.13.0` 不保证有管理页入口。旧核心不会注册管理接口，聊天功能仍可用。接入方式遵循 [AstrBot 官方插件视图文档](https://docs.astrbot.app/dev/star/guides/plugin-pages.html)，无需额外端口或独立管理密码。

- **全部历史**：按全局图库编号升序/降序分页，筛选编号、用户 QQ、群号、日期、提示词/昵称/管理备注；预览、下载、编辑显示昵称/图库提示词/备注，单条或批量移入回收站。
- **按用户管理**：跨群按 QQ 汇总，支持 QQ 和历史昵称搜索，点击用户直接进入其图片管理列表。
- **插件设置**：覆盖 `_conf_schema.json` 中的全部设置，提供人物表单与参考图上传；保存到 AstrBot 配置并立即应用，保留限流数据库。

删除采用**可恢复回收站**：聊天历史查询、随机图库、个人画廊立即隐藏记录，并解除该图片的本体参考关联；原图仍在磁盘，不释放空间、不返还配额。恢复保留编号，不会覆盖当前本体参考图。原始请求人 QQ、群号、生成时间和任务记录不可改写；编辑提示词仅更新图库文字。

所有接口要求 Dashboard 登录身份，图片通过受鉴权的 Bridge 读取。密钥不回显，只有勾选替换后才提交新值（勾选后留空表示清空）。并发修改会提示刷新；有生图后台任务时暂不接受历史变更和设置保存，查询不受影响。图库升级自动补齐管理字段，既有图片、编号及元数据保持。

上传人物图存于 `data/plugin_data/astrbot_plugin_img_gener/admin_references/`，保存设置后生效。回收站与上传图不受临时清理影响，移除人物关联不会删除上传文件。本页历史指永久成功图库；失败、拒绝等运行记录仍使用 `/生图状态` 查询。

## 必要配置

重载插件后，在插件设置里至少填写：

```text
生图 API → API Base URL = https://uuapi.cc/v1
生图 API → UUAPI API Key = sk-你的密钥
生图 API → 生图模型 = gpt-image-2
安全审核 → 审核 API Base URL = https://uuapi.shop/v1
安全审核 → 审核 API Key = sk-你的审核密钥
安全审核 → UUAPI 审核模型 = 你在审核站已开通的聊天模型 ID
安全审核 → 识图模型（视觉）= 审核站已开通的多模态模型 ID（可选，用于生成后评价图片）
```

两个 API Key 都可写成 `$环境变量名`。例如生图填写 `$UUAPI_IMAGE_API_KEY`、审核
填写 `$UUAPI_REVIEW_API_KEY`，避免把密钥明文保存在插件配置文件中。

UUAPI 当前文档给出的同步接口是：

- 文生图：`POST /v1/images/generations`，JSON 请求，优先读取 `data[0].b64_json`。
- 参考图：`POST /v1/images/edits`，`multipart/form-data` 请求，图片字段名为 `image`。

插件同时兼容 `data[0].url` 返回；URL 图片会先经过协议、私网地址和文件大小检查，再下载到插件数据目录。

## 安全审核

默认审核分三层：

- 本地硬规则会直接拒绝政治相关、未成年人色情、性暴力、真实人物色情侵害和管理员禁用词等内容。
- LLM 审核器根据内置政策返回严格 JSON 判定。
- GPT Image 上游默认的 `auto` 审核继续生效。

LLM 审核固定走独立的 OpenAI-compatible `/chat/completions`，默认地址为
`https://uuapi.shop/v1`，使用独立审核 Key，绝不会把生图 Key 发给审核站。启用 LLM
审核时必须填写审核模型 ID；插件不会回退到 AstrBot 当前聊天模型。

建议保持“审核故障时拒绝请求”开启。否则审核模型超时、网络故障或返回格式异常时会继续尝试生图，不适合公开群。

管理员可在设置里追加：

- `管理员禁用词`：在任务受理前检查，命中后直接拒绝，不显示“正在生图”且不创建
  后台任务；拒绝仍会计入调用频率。
- `自定义审核政策`：替换内置的 LLM 审核政策。本地硬规则仍会保留。
- `在日志记录原始提示词`：默认关闭；关闭时日志只记录提示词哈希、审核分类、用户 ID 和群 ID。

审核能显著降低滥用，但不是法律或平台合规的替代品。公开部署前仍应根据所在地区、聊天平台规则和社区人群调整政策。

## 用户和群限流

限流数据保存在：

```text
AstrBot/data/plugin_data/astrbot_plugin_img_gener/rate_limits.sqlite3
```

实际根路径由 AstrBot 的 `get_astrbot_plugin_data_path()` 决定。重载插件或重启 AstrBot 不会重置配额。

默认值：

| 规则 | 默认值 | 计数语义 |
|---|---:|---|
| 单用户最短调用间隔 | 60 秒 | 每次被准入的调用 |
| 单用户调用窗口 | 10 分钟最多 3 次 | 审核拒绝、上游失败也计入调用 |
| 单用户成功生图 | 每小时 5 张 | 成功拿到合法图片才计数 |
| 同群最短调用间隔 | 15 秒 | 群内所有用户共享 |
| 单群成功生图 | 每小时 20 张 | 私聊不套用群配额 |
| 单群并发 | 1 | 防止同群连续堆积任务 |
| 全局并发 | 2 | 管理员也不能绕过 |

插件使用 SQLite 事务和“生成中预留位”，因此两个同时到达的请求不能一起越过最后一个配额。上游真正返回图片后才提交成功生图计数；审核失败或 API 失败会释放预留位，但调用频率计数仍保留。

任务隔离在后台调度之前完成：插件保存本次发起人的 QQ、群/私聊统一消息来源、中文提示词、人物参数，并把回复消息中的引用图片立即读成不可变字节快照。后台结果通过保存的会话来源发送，再按冻结的 QQ 号 `@` 发起人，不再依赖后续可能变化的消息事件。每次受理会返回 `#任务号 / P-提示词哈希`，成图使用同一标识，失败和评价也携带对应任务号。

所有数值都可在插件设置的“频率与配额”中修改。`最多成功生图数` 设为 `0` 表示关闭对应窗口配额。

## 人物参考清单

在插件设置中打开“人物参考清单 → 人物列表”，新增一个“角色位 01”条目：

```text
人物名称：可可子
别名：可可、Coco
参考图片：上传 1～3 张清晰设定图
旧版无图后备设定：（兼容保留，当前版本不会自动注入）
```

再新增一个“角色位 02”条目配置菌菌，以此类推。**每个角色位拥有独立的图片库**：
打开某个角色的参考图片选择器时，只会看到该角色位自己上传的图片，不会看到其他
角色的图片或生成结果，互不干扰。因此新增角色时请选择一个尚未使用的角色位。

“人物参考（旧版共享图库）”模板仅为兼容旧版本配置保留：它下面的所有条目共用
同一个图库。已配置的老角色可以继续使用，也可以把图片重新上传到空闲角色位后
迁移过去。

有可用参考图时，图片本身是该人物身份和外观的最高优先级依据。插件**不会**把
“无图时后备设定”注入最终提示词，也不会擅自补充发色、服装或默认构图；只有 AI
整理出的中文生图提示词中由用户明确提出的改动才会保留。没有任何可用人物参考图时，
插件直接使用本次中文提示词走文生图，不会因角色未配置或图片缺失而拒绝。

之后用户说“画一张可可子和菌菌在咖啡店聊天”，插件会：

1. 从原始请求和 AI 整理后的中文提示词中匹配名字或别名；
2. 按人物清单顺序收集可用参考图，并记录每张图片所属人物；
3. 给图片分配统一的 `REF-01`、`REF-02` 编号；
4. 使用 UUAPI `/v1/images/edits` 实际上传参考图。

默认最多携带 4 张参考图。提到已配置人物但图片丢失、过大或格式不支持时，
如果最终一个人物参考图都没有，插件会按用户提示词直接文生图。已经携带部分人物参考图、
但其他已匹配人物仍缺图时，`部分人物缺少参考时拒绝生图` 可阻止混合“有身份锚点”和
“无身份锚点”的角色，避免同框人物一致性失衡。

### QQ 用户画像档案

用户明确要求画自己，或在生图请求中 `@` 指定 QQ 用户时，插件会在 AstrBot 插件数据
目录中按 QQ 号建立动态人物档案。角色主名称始终使用 QQ 号，当前群名片/昵称作为别名：

- 每次用户描述自己时都会读取当前群名片或昵称并追加到别名；
- 单个别名最多 20 个字符，超出部分不会写入档案；
- 每个 QQ 只保留 0 或 1 张当前本体参考图，不会再同时上传多张历史画像；
- 没有本体参考图时按用户本次描述进行首次文生图，不受静态人物“缺图拒绝”影响；
- 新生成的本人画像会进入永久图库，并替换为该 QQ 唯一的本体参考图；
- 手动上传的参考图存于插件长期数据目录；以后被新画像替换时只更新档案关联，永久图库
  中的历史生成图不会删除。

聊天模型为请求人本人画像时，应在 `portrait_user_qqs` 传入 `self`；确认了 `@` 用户
或 QQ 号后传入对应 QQ。已存在的唯一别名也可自动匹配。若同一别名属于多个 QQ，插件
不会猜测，而会返回如下候选，要求 AI 先让用户回复数字序号：

```text
1.（10001）（当前群名片甲）
2.（10002）（当前群名片乙）
```

确认后 AI 再次调用 `generate_image`，并在 `portrait_user_qqs` 中传入选中项的 QQ 号。
在确认之前不会建立后台任务，也不会回复“正在生成”。

查看与替换：

- 普通用户使用 `/生图参考图` 查看自己的当前图片；
- 发送一张图片，或回复一条只含一张图片的历史消息，再使用 `/生图参考图 设置`
  即可替换自己的当前图片；
- AstrBot 管理员使用 `/生图参考图 列表` 查看全部 QQ 档案和设置状态；
- 管理员使用 `/生图参考图 <QQ号>` 查看指定用户，使用
  `/生图参考图 设置 <QQ号>` 替换指定用户；
- Agent 可调用 `get_user_portrait_reference` 发送档案中的真实图片。普通用户仍只能
  查询自己，只有 AstrBot 管理员能指定其他 QQ。

### 多角色同框

多个角色同框时，默认**每个角色只携带第 1 张可用参考图**（可在设置中通过
`多角色时每角色参考图上限` 调整；单角色场景不受影响，仍可携带多张）。人物对照
同时写入三处：

- 最终提示词逐图声明 `REF-01 = 角色「可可子」`、`REF-02 = 角色「菌菌」`；
- 分别上传时文件名为 `reference_01_可可子.png`、`reference_02_菌菌.png`；
- 自动拼合时，每个格子底部绘制 `REF-01 | 可可子` 这样的可见标签，标签位于独立
  底栏，不覆盖人物图像。

参考规则只要求各 REF 不得互换、混合或合并，并要求用户没有明确修改时尽量保持图中
人物原样；不会再添加“左右并排”等构图建议，也不会把管理员后备设定重新描述一遍。

如果仍然偶尔出现漏画角色，把“参考图上传模式”保持为默认的 `自动` 即可——该模式下
多角色同框时会把所有参考图拼成一张带标签的格子图（单个 image 字段上传）。部分网关
对重复 image 字段支持不稳，可能只转发第一张；拼合模式可以绕开这个问题。追求最高清晰度
时可选 `分别上传多图`。日志会记录每次实际使用的上传模式与文件名，便于排查网关是否
丢弃了多图。

参考图越多，模型越容易把角色搞混，建议保持每人 1 张。同框人物数超过
`单次最多携带参考图` 时，多出的人物无法携带参考图；只要已经携带了部分人物参考，
严格模式仍会拒绝这类不完整映射，避免生成缺少角色的图片。

### 引用历史消息图片

用户回复或引用一条包含图片的历史消息后再要求生图，插件会读取 `Reply` 引用链中的
图片，并把它们作为额外参考图上传到 `/v1/images/edits`。AI 生成的中文提示词应说明
引用图片用于人物、物体、构图还是风格参考。

默认规则：

- 最多携带 2 张引用图片，可通过 `单次最多引用历史图片` 调整；
- 引用图片与管理员配置的人物参考图共同受 `单次最多携带参考图` 限制；
- 仅支持 PNG、JPEG 和 WebP，并复用单张参考图大小上限；
- 图片失效、无法读取、格式不支持或数量超限时明确拒绝，不会静默退化为纯文生图；
- 多张参考图在自动模式下会拼成格子图，避免网关只转发第一张；
- 只读取被引用历史消息里的图片，不会自动携带当前消息直接附加的图片。

引用图片沿用同一套全局 REF 顺序：分别上传时会命名为
`reference_03_user_quote_01.png` 等；进入拼图时也会显示相同 REF 编号。若引用图被用作
人物参考，用户未明确要求改变时同样要求尽量保持原人物，不自行补充外观。

管理员固定人物参考图仍按人物名和别名自动匹配。引用图片只在当前任务内存中使用，
不会保存到人物图库。
## 使用方式

正常聊天示例：

```text
帮我画一张可可子在雨后的车站撑透明伞的插画，竖图，中等质量。
```

聊天模型应自动调用：

```text
generate_image(
    prompt="雨后的火车站站台，可可子手持透明雨伞，地面倒映暖色灯光，细腻日系插画，竖向构图",
    size="1024x1536",
    quality="medium",
)
```

其中 `prompt` 必须是聊天模型根据用户需求整理出的、可直接用于生图的完整中文提示词，
不能传英文翻译，也不能直接复制“帮我画一张……”这类对话原文。

`generate_image` 会立即向 LLM 返回“开始生图提示语 + 当前队列概况 + 预计耗时”，
随后在后台完成安全审核、UUAPI 生图、图片下载和发送。这样不会让耗时的生图请求
占满 AstrBot 的工具调用时限。AstrBot 的 `provider_settings.tool_call_timeout`
默认通常为 60 秒，而一次审核加参考图生成通常需要约 3 分钟；插件的后台模式不
依赖调大该值。工具描述已明确告诉 LLM“这只是受理、图片尚未生成”，避免它把受理
误报成已完成。

群内多人接连请求时，Agent 必须把每次工具调用限制在当前发言人和当前消息，不得合并
其他群友最近的提示词、引用图或画像对象。受理结果中的 `#任务号 / P-提示词哈希` 应
原样转述，用户即可用相同标识核对后续成图、失败和评价消息。

生成完成后，插件会：

1. 把成功图片永久归档，并分配简单自增的图库编号；
2. 若这是 QQ 用户画像，替换对应 QQ 当前唯一的本体参考图；
3. 发送一条 `@发起人 + 任务号/提示词哈希 + 图库编号 + 尺寸/质量/总用时 + 实际生图提示词 + 图片`；
4. 再调用“安全审核 → 识图模型”对图片给出 1~3 句简短评价并 `@发起人` 发送；
   识图失败时退回为“仅根据提示词”评价。可在“生成参数 → 生成后发送简短评价”
   关闭该评价。

插件也提供几个测试命令：

```text
/生图 一只戴宇航头盔的橘猫，儿童绘本风格
/生图人物
/生图参考图
/生图参考图 设置
/生图参考图 列表
/生图状态
/生图历史
/生图历史 1002
/生图历史 随机
/生图历史 随机 6
/画廊
/画廊 10
/画廊 -5
/画廊 [123 151 488 622]
```

`/生图` 命令收到请求后会立即发送同一条可配置提示语并转入后台生成，释放当前
会话，因此生成期间仍可调用 `/生图状态`。完成后插件主动发送图片与明确的结果，
受理回执与成功结果会附带相同任务号和提示词哈希，成功结果也会附带从任务受理到
图片发送完成的总用时。提示语可在
“生成参数 → 开始生图提示语”中修改。

`/生图` 的格式固定为 `/生图 提示词`，中间不需要也不会解析尺寸参数，始终使用
“生成参数 → 默认生图尺寸”。新安装默认使用 `816x816`；已有安装若配置中已保存
旧默认值，可在插件设置中手动选择“小方图 816×816（较快）”。默认尺寸不必重复
加入“允许使用的尺寸”清单；该清单只限制 LLM 工具额外选择的尺寸。确认消息与
`/生图状态` 会显示实际尺寸。

`gpt-image-2` 要求两条边均为 16 的倍数且总像素不少于 655,360，所以不能使用
`512x512`。需要进一步缩短生成时间时，可同时把“默认质量”设置为 `low`。

`/生图状态` 会显示权威结论、内存任务池、当前阶段、已用时间、SQLite 并发预留、
用户调用/生图余量与冷却、本群生图余量与冷却，以及本人最近 3 条记录。查询结果会
明确区分：任务确实处理中、当前无任务但最近一次失败/拒绝/完成、插件根本没有收到
生图调用。模型、接口、密钥、审核配置等管理信息不会展示给普通用户。

`/生图历史` 现在对应**永久成功图片图库**：不带参数时返回图片总量和编号规则；传入
纯数字编号时返回请求人 QQ/当时昵称、提示词、图片、完成时间、尺寸质量和总用时。
`/生图历史 随机` 只返回一张随机图片，不附带资料；`/生图历史 随机 2～9` 会把随机
图片拼成一张整齐网格后返回，4 张为四宫格、6 张为 3×2、最多 9 张为九宫格。

### 个人画廊

`/画廊` 将本人最近 20 张成功归档的图片汇总为一张图，标题为 **用户名称の画廊**，
使用发起者当前昵称。浅色卡片下方保留真实图库编号和北京时间日期，可通过
`/生图历史 编号` 查看原图及详情。

| 指令 | 选图方式 |
| --- | --- |
| `/画廊` | 本人最近第 1～20 张 |
| `/画廊 10` | 本人最近第 1～10 张；数量支持 1～20 |
| `/画廊 -5` | 本人最近第 5～24 张，包含第 5 张，向更早取最多 20 张 |
| `/画廊 [123 151 488 622]` | 按输入顺序拼接这 4 个图库编号，方括号必须输入 |
| `/画廊 [10]` | 只展示图库编号 10；与取最近 10 张的 `/画廊 10` 不同 |

默认、数量和 `-N` 模式按当前 QQ 跨群汇总，仅包含本人成功归档的图片，并按归档顺序
从新到旧排列。不足指定数量时展示实际数量；没有图片或起始位置越界会明确提示。
正数数量、`-N` 和方括号编号队列三种参数形式不能混用。

指定编号沿用 `/生图历史 <编号>` 的全图库访问范围，允许选择其他用户已经归档的图片。
队列最多 20 项，保留顺序和重复项；不存在的编号会一次列出并停止本次拼图。
已有记录的图片文件缺失或损坏时，保留对应卡位并显示无法读取，避免序号错位。

布局随数量调整，4 张为 2×2、9 张为 3×3、20 张为 4×5。横竖图片完整缩放，不裁切主体；
最近图片模式在仍有更早图片时显示下一组指令。画廊使用本地排版，不调用生图或审核 API、
不消耗生图配额。拼图保存在临时输出目录，按 `retention_days` 清理，不写入永久图库。
插件附带 [Noto Sans SC](https://github.com/notofonts/noto-cjk) 中文字体，遵循
[SIL OFL 1.1](assets/fonts/OFL.txt) 许可，Linux 环境无需另行安装系统中文字体。

永久图库位于 AstrBot 的 `data/plugin_data/astrbot_plugin_img_gener/gallery/`，不会受到
插件源码更新或 `retention_days` 清理影响。`/生图状态` 中的“我的最近记录”仍用于查看
本人任务终态，包括入队前拒绝、审核拒绝、限流、HTTP 502、发送失败、取消和重启中断；
这部分运行记录才会跟随配置的保留天数清理。升级前旧图片缺少完整元数据，不会自动
补录进永久图库。

插件同时提供 Agent 工具 `get_image_generation_status`。用户询问进度、是否真的入队、
最近失败原因、历史、个人/群余量或冷却时，聊天模型必须调用该工具，不能根据先前的
“已受理”回复自行判断仍在生成。工具默认返回最近 5 条本人记录，可查询 1～20 条。

用户要求查看自己的当前本体参考图时，Agent 应调用 `get_user_portrait_reference`；
该工具会实际发送档案图片，并保持与聊天指令相同的本人/管理员权限边界。

如果聊天模型一直不调用工具，请先在 AstrBot WebUI 的 Tool 管理中确认
`generate_image`、`get_image_generation_status` 和 `get_user_portrait_reference`
均已启用，并确认当前聊天模型支持 Function Calling。

## 开发验证

```powershell
python -m pip install -r requirements.txt
python -m pip install pytest ruff
python -m pytest
ruff check .
```

涉及真实 UUAPI 的端到端测试不会在单元测试中自动执行，避免意外扣费。建议先把配额调小，通过 `/生图` 做一张低质量测试图，再启用公开群。
